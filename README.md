## Анализ сложности и ограничения

### Сортировки
Обе функции принимают `list` или `tuple`, возвращают новый отсортированный список и вызывают `TypeError` при неверном типе входа.

* **`selection_sort`**: сложность $O(N^2)$ в любом случае, дополнительно занимает $O(N)$ памяти на копирование списка.
* **`heap_sort`**: сложность $O(N \log N)$ в любом случае (не деградирует на отсортированных данных)

### Очередь с приоритетами (`PriorityQueue`)
* **`push`**: $O(N)$ (поиск места для вставки по приоритету).
* **`pop` / `peek` / `len` / `bool`**: $O(1)$. При обращении к пустой очереди выбрасывается `EmptyQueueError`.

### Рекуррентная задача (`gcd`)
* Сложность итеративного и рекурсивного вариантов: $O(\log(\min(a, b)))$.
* **Ограничение рекурсии в Python:** по умолчанию глубина стека вызовов ограничена примерно 1000 вложенными вызовами (`sys.getrecursionlimit()`), при превышении возникает `RecursionError`. Итеративная версия лишена этого ограничения.

## Бенчмарк
* Для каждого размера ($N = 100, 1000, 10000$) и типа данных выполняется минимум 5 повторов.
* Генерация массива происходит до запуска таймера, а перед каждым прогоном создаётся независимая копия (`data.copy()`).
* **Выводы по результатам:** при росте размера данных в 10 раз (с 1 000 до 10 000) время `selection_sort` увеличивается примерно в 100 раз (подтверждает $O(N^2)$), тогда как `heap_sort` замедляется лишь примерно в 13 раз (подтверждает $O(N \log N)$) и стабильно работает на всех типах входных данных.
